- **All 5 tabs render without console errors**: Home, Map (+ Trips), Remote, In-car, Car. Alerts reachable via the bell.
- **Web-first**: the browser app is the priority now; Android packaging comes later.

## 2. How the real API was unlocked

1. Pulled the official app `com.msil.suzukiconnect_generation_2` v1.1.24 from the Play-linked XAPK.
2. Decompiled with JADX → the complete endpoint map (`docs/SUZUKI-CONNECT-API.md`).
3. Decoded the native `client_id` / `client_secret` statically: disassembled `libnative-lib.so` with capstone + pyelftools, found `reveal()` XORs with `SuzukiCipherKey`.
4. Verified credentials live:
   - `POST /api/auth/otp/request` (mobile + appVer + device_id + grant_type:"otp" + client_id/secret) → SMS OTP.
   - `POST /api/auth/otp/validate` (oai + otp + same fields) → access_token + refresh_token.
   - `POST /api/dashboard` with `Authorization: Bearer` + `{origin, contract_id, deviceId}` → live status.

## 4. Known limitations / not yet wired

- **Trips** (`/api/trip/tripHistory`) and **Alerts** (`/api/profile/alertHistory`) return a Cloudflare 400 when called with our payload. Dashboard works through the same proxy, so the issue is the exact request shape (likely field/date formats or content type). Next step: capture the real app's request for these two and mirror it. Until then Trips and Alerts show demo data.
- **Remote commands** (lock, hazard, AC, immobilizer, valet) go through `remote/api/remoteapi/*` with an `r_key` header — not yet attempted (deliberately, to avoid real-world side effects before the read path is solid).
- **Smartplay Pro (Bluetooth head-unit control)** and **Pro Sync (infotainment updates)**: UI placeholders on the In-car tab, not connected. Needs a Bluetooth protocol capture in the car.
- **CORS**: the API sends no allow-origin header. Web uses the `/scapi` proxy in `devserver.js`. When we do the Android build, Capacitor native HTTP bypasses this.
- **Ponytail skill** installed earlier today (all six, frontmatter validated).

## 5. Notable engineering notes

- A `const`-reassignment in the first live-sync attempt silently crashed startup and left mock values on screen. Fixed by rewriting the live layer (`live.js`) with no global reassignments.
- The service worker cached an old bundle, which made debugging confusing until cache+registrations were cleared. `devserver.js` sends `Cache-Control: no-store` now, and the SW is network-first.
- Dev server must stay running for the web app to reach the API (`/scapi` proxy). If the server dies, the page can still load from cache and show stale/mock data.
